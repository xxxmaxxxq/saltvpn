# 📖 RUNBOOK — развёртывание с нуля

Инструкция рассчитана на то, что вы **никогда не разворачивали серверы**.
Команды выполняются копипастом. Время: ~1 час.

---

> **Сначала посмотрите бота локально.** Прежде чем платить за серверы,
> запустите интерфейс у себя: [`QUICKSTART_LOCAL.md`](QUICKSTART_LOCAL.md).
> Это 5 минут и ноль рублей.

## Этап 0. Что нужно купить заранее

| Что | Где | Цена ориентировочно |
|---|---|---|
| VPS для мастера (Германия/Финляндия), 2 vCPU / 4 GB, Ubuntu 24.04 | любой европейский хостер | 5–8 €/мес |
| VPS для ноды NL, 1–2 vCPU / 2 GB | хостер в Нидерландах | 4–6 €/мес |

| Мерчант Platega + токен CryptoPay | сайты сервисов | бесплатно |

**Про домен.** Он нужен только панели и Mini App. Для самих VPN-нод (Reality)
домен и сертификаты НЕ нужны — маскировка идёт под чужой SNI.

## Этап 1. Домен → мастер-сервер

В панели регистратора создайте A-запись:

```
vpn.ваш-домен.ру   A   <IP мастер-сервера>
```

Проверка (через 5–15 минут):
```bash
ping vpn.ваш-домен.ру
```

---

## Этап 2. Подготовка мастер-сервера

Подключаемся по SSH:
```bash
ssh root@<IP мастера>
```

Ставим всё необходимое одной командой:
```bash
bash scripts/install-master.sh   # репозиторий приватный: файл берётся из клона, а не по ссылке
```

Скрипт: обновит систему, поставит Docker + Docker Compose, настроит фаервол
(откроет только 22, 80, 443), включит fail2ban и создаст папку `/opt/vpn-service`.

2. Логин/пароль — из `.env` (`MARZBAN_USERNAME` / `MARZBAN_PASSWORD`).

## Этап 6. Подключение ноды

На **мастере** в панели Marzban: *Nodes → Add Node* → скопируйте сертификат.

На **сервере ноды**:
```bash
ssh root@<IP ноды>
bash scripts/install-node.sh   # репозиторий приватный: файл берётся из клона, а не по ссылке
nano /var/lib/marzban-node/ssl_client_cert.pem   # вставьте сертификат из панели
docker compose -f /opt/marzban-node/docker-compose.yml restart
```

В панели нода должна стать **connected** (30–60 секунд).

Затем добавьте ноду в базу сервиса:
```bash
cd /opt/vpn-service/vpn-service-project
docker compose -f docker/docker-compose.yml exec api python -m app.cli add-node \
  --code nl-1 --location nl --host <IP ноды> --marzban-node-id <ID из панели>
```

## Этап 7. Платежи

1. **ЮKassa (СБП, основной способ):** см. отдельный раздел ниже.

### ЮKassa: СБП для самозанятого

Самозанятый не может подключить торговый эквайринг напрямую — для этого
нужен статус ИП. Но принимать оплату через платёжный сервис он вправе:
договор с банками держит сам сервис. ЮKassa работает с самозанятыми и
передаёт чек в ФНС за вас, поэтому пробивать каждый платёж вручную в
«Моём налоге» не придётся.

**Подключение**

1. Кабинет ЮKassa → регистрация со статусом «Самозанятый», привязка
   аккаунта «Мой налог».
2. *Интеграция → Ключи API* → скопировать **shopId** и **секретный ключ**.
3. *Интеграция → HTTP-уведомления*:
   - URL: `https://vpn.ваш-домен.ру/webhook/yookassa`
   - события: `payment.succeeded` и `payment.canceled`
4. В `.env`:

```bash
YOOKASSA_ENABLED=true
YOOKASSA_SHOP_ID=ваш_shop_id
YOOKASSA_SECRET_KEY=ваш_секретный_ключ
YOOKASSA_RECEIPT_EMAIL=почта_для_чеков@example.com
```

5. `bash scripts/deploy-master.sh restart`

Кнопка «🏦 СБП» появится в боте сама: список способов оплаты строится
из тех провайдеров, у которых заполнены ключи.

**Как устроена защита от поддельных оплат**

ЮKassa, в отличие от Platega, **не подписывает уведомления** — приходит
обычный POST без HMAC. Если верить телу такого запроса, любой, кто знает
адрес ручки, сможет выписать себе подписку одним `curl`. Поэтому проверки
две, и обе обязательны:

1. Адрес отправителя сверяется с официальными сетями ЮKassa
   (`app/payments/yookassa.py`, `YOOKASSA_NETWORKS`).
2. После этого сервис **сам спрашивает ЮKassa** по её API, оплачен ли
   платёж. Дни начисляются только если она ответила `status=succeeded`
   и `paid=true`.

Тело уведомления источником истины не считается. Если ЮKassa недоступна
в момент проверки — дни не начисляются, уведомление отклоняется с кодом
400, и ЮKassa повторит его позже (она это делает в течение суток).

Отсюда требование к сети: контейнер `api` должен ходить **наружу** на
`api.yookassa.ru`. Если закроете исходящий трафик — оплаты перестанут
подтверждаться, при этом деньги у людей спишутся.

**Проверка**

```bash
docker logs -f salt_api | grep -i yookassa
```

Оплатите тариф на минимальную сумму со своего телефона. В логе должно
появиться создание счёта, затем уведомление, затем начисление. Если
видите `Уведомление ЮKassa с чужого адреса` — Caddy не проставляет
`X-Real-IP`, проверьте `docker/Caddyfile.master`.

```bash
make restart
```

## Что делать, если…

**Бот не отвечает.**
`make logs` → смотрим ошибку. Частые причины: неверный `BOT_TOKEN`,
не выпустился сертификат (проверьте A-запись домена), контейнер `bot` в статусе
`restarting`.

**Ноду заблокировали.**
Auto-Healing сработает сам в течение 5 минут и пришлёт вам уведомление. Если он
исчерпал все варианты — закажите у хостера дополнительный IP и выполните:
```bash
docker compose -f docker/docker-compose.yml exec api python -m app.cli set-node-host --code nl-1 --host <новый IP>
```

**Платёж прошёл, а дни не начислились.**
`make logs` → ищем `webhook`. Проверьте, что URL вебхука у провайдера указан
правильно и совпадает секрет. Начислить вручную: `/give <tg_id> <дней>` в боте.

**Кончилось место на диске.**
```bash
docker system prune -af --volumes   # осторожно: удалит неиспользуемые образы
```

**Нужно откатиться на предыдущую версию.**
```bash
git log --oneline -5      # находим хэш рабочего коммита
git checkout <хэш> && make up
```
