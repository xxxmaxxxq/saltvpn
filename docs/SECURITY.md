# 🔒 Безопасность

## 1. Принципы

1. **Меньше данных — меньше риск.** Сервис не хранит паспорта, почты, реальные имена.
   Идентификатор пользователя — только `telegram_id`.
2. **Не логируем трафик.** В конфигах Xray на нодах `log.loglevel: none`,
   `access: none`. Кто на какой сайт ходил — технически не восстановить.
3. **Секреты не в коде.** Только в `.env` (в `.gitignore`) и GitHub Secrets.
4. **Приватные ключи не в БД.** Ключи Reality генерируются на нодах и остаются там.

---

## 2. Чек-лист перед запуском в прод

- [ ] Все пароли в `.env` заменены на сгенерированные (`openssl rand -hex 24`).
- [ ] `ENV=production` (выключает `/docs` и подробные трейсбеки).
- [ ] Вход по SSH только по ключу, `PasswordAuthentication no`.
- [ ] Фаервол: открыты только 22, 80, 443 (делает `install-master.sh`).
- [ ] Порты Postgres (5432) и Redis (6379) **не** проброшены наружу в compose.
- [ ] Панель Marzban доступна только по HTTPS и не на стандартном пути.
- [ ] `fail2ban` активен.
- [ ] Бэкапы настроены и **проверено восстановление** из дампа.
- [ ] `git log -p | grep -i -E "(token|password|secret)"` — ничего не нашлось.

---

## 3. Проверка вебхуков

Любой может отправить POST на `/webhook/platega`. Поэтому **каждый** вебхук
проверяется криптографически:

| Провайдер | Проверка |
|---|---|
| Platega | HMAC-SHA256 тела на `PLATEGA_WEBHOOK_SECRET`, сравнение через `hmac.compare_digest` |
| CryptoPay | HMAC-SHA256 тела на ключе `SHA256(CRYPTOPAY_TOKEN)` |
| Telegram | секретный токен в заголовке `X-Telegram-Bot-Api-Secret-Token` |
| Mini App | HMAC-подпись `initData` по схеме Telegram WebApp |

Дополнительно — идемпотентность по `UNIQUE (provider, external_id)`: даже
валидный повторный вебхук не начислит дни дважды.

---

## 4. Защита от злоупотреблений

| Угроза | Защита |
|---|---|
| Фарм триалов | Один триал на `telegram_id` + хэш IP в Redis (TTL 30 дней) + эвристика возраста аккаунта |
| Шеринг ключа на десятки людей | Лимит одновременных IP в Xray + алерт при аномалии |
| Спам-нажатия кнопок | Rate-limit в Redis: 20 действий/мин на пользователя |
| Накрутка рефералов | Реферал засчитывается только после **реальной оплаты**, самоприглашение заблокировано |
| Подбор `subscription_token` | Токен 32 байта из `secrets.token_urlsafe` |

---

## 5. Персональные данные

Сервис обрабатывает: Telegram ID, username, историю платежей (суммы и даты),
служебные IP-хэши для антифрода. Этого достаточно для работы биллинга и не
образует чувствительного профиля.

При удалении аккаунта (`/delete_me`): пользователь отключается в Marzban,
`telegram_id` и `username` анонимизируются, платежи остаются обезличенными
(нужны для бухгалтерии).

## 6. Реакция на инцидент

**Утечка `.env`:**
1. Немедленно перевыпустить `BOT_TOKEN` в @BotFather.
2. Сменить пароли Postgres/Redis/Marzban, перезапустить стек.
3. Перевыпустить ключи платёжных провайдеров.
4. Проверить логи на нетипичные запросы к `/internal/*`.

**Компрометация ноды:**
1. Отключить ноду в панели (пользователи автоматически уедут через Auto-Healing).
2. Уничтожить VPS целиком, не «чистить» — поднять новый из `install-node.sh`.
3. Ключи Reality на новой ноде генерируются заново.

**Блокировка бота Telegram:**
1. Поднять резервного бота (`BACKUP_BOT_USERNAME`) — база и подписки общие.
2. Оповестить пользователей через инфо-канал.
3. Ссылки-подписки продолжают работать: доступ к VPN у людей не пропадает.
